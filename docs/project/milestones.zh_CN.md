# 语音日记 — 项目里程碑

状态：草稿，2026-10-26。范围来自[产品方案](../product/product-spec.zh_CN.md)、
[服务端方案](../technical/server.zh_CN.md)、[设备端方案](../technical/client.zh_CN.md)与
[视觉设计语言](../design/visual-language.zh_CN.md)。

## 1. 排序依据

两条规则决定顺序：

1. **服务端先做。** 它是唯一不需要硬件就能验证的部分，而设备端从"录音"之后的每一步都要
   有东西可连通。一个单二进制加 `curl` 加一个素材文件，第三天就是可用的靶子。
2. **每个里程碑都以"可演示"收尾。** 没有"半层"的里程碑；每次收尾都留下一个能展示增量
   的构建，哪怕另一半还是桩。

```text
M0 骨架 ──► M1 服务端 ────────────────┐
    │                                 │
    └────────► M2 录音 ──► M3 翻阅 ────┴──► M4 联网 ──► M5 打磨
```

M2 可以与 M1 并行；M3 依赖 M2；M4 需要 M1 和 M2 都完成。

## 2. 里程碑

### M0 — 骨架（1 天）

| 项 | 交付物 |
| --- | --- |
| 服务端骨架 | `server/` 模块、配置解析、SQLite 打开与建表、`GET /health`、一个能过的测试 |
| 固件骨架 | 新的 `partitions.csv`、调参后的 `sdkconfig.defaults`、demo 页换成只画一张空卡片的 `memo_app` |
| 可追溯 | 三份设计文档从 `README.md` 链过去 |

**退出条件：** `go build ./...`、`go test ./...`、`./tools/validate.sh --static`、
`./tools/validate.sh --firmware` 全过。烧进设备后屏幕上只有一张卡片，别的什么都没有。

**演示：** 一个进空备忘页的固件 + 一个能应答 `/health` 的服务端。

### M1 — 服务端端到端可用（3–4 天）

| 项 | 交付物 |
| --- | --- |
| 容器 | 解析、校验规则、拒绝码 |
| 音频 | Opus 解码为 WAV，头部与时长交叉校验 |
| 存储 | memos / devices 表、文件布局、软删除 |
| 接口 | 上传（幂等）、游标列表、详情、Range 音频、PATCH、DELETE、重跑转写 |
| 任务 | `fake` 提供方、退避、崩溃恢复 |
| 发现 | mDNS 广播 `_voicememo._tcp` |

**退出条件：**

- `curl` 脚本对一个素材容器走完 上传 → 列表 → 详情 → 音频 → PATCH → DELETE，每一步的
  状态码都符合预期。
- 重复的 `X-Memo-Id` 只产生一行记录、一个任务。
- 转写中途杀掉进程再启动，任务会被重跑。
- 解码 5 分钟容器在开发机上低于 200 ms。

**演示：** 从笔记本用 `curl` 传一段真实录音，从 `GET /memos` 读到文本，把 WAV 拉回来放。

### M2 — 设备能录音、能存住（3–4 天）

| 项 | 交付物 |
| --- | --- |
| 逻辑 | `memo_state`、`memo_text`、`memo_time` 及对应宿主测试 |
| 录音 | 录音页、Opus 编码、4 KB 批次、spool 追加、停止时重写头部 |
| 持久化 | SPIFFS 挂载、启动扫描、`.memo` / `.sent` / `.bad` 命名 |
| 限制 | 5 分钟上限与 04:30 提示 |

**退出条件：**

- 长按 OK 三秒录音、停止：出现一个 `.memo` 文件，头部有效，帧数与时长自洽。
- 断电重启后文件仍在，开机即在列表里出现。
- 录满五分钟自动停止。
- 宿主测试覆盖全部状态迁移、截断场景、退避档位。
- 按键唤醒守卫的接线随输入任务一并恢复，并在 M0 随基线入口一起移除的那条契约测试
  重新加回来。
- 录音期间屏幕刷新的同时，听不到爆音。

**演示：** 录一条，重启，它还在；打开它，本地播放（播放器可以在这一步做完，虽然联网播放
要等到 M4）。

### M3 — 能翻能读（3–4 天）

| 项 | 交付物 |
| --- | --- |
| 字体 | `lv_font_conv` 子集、带负例的覆盖测试、fallback 描述符 |
| 列表 | 日期分组、选中、状态点、电量、提示栏 |
| 详情 | 折叠/展开、播放条、接上本地播放 |
| 设置 | 音量、自动息屏、深度休眠、自动播放、关于——含子页规则 |
| 风格 | 视觉设计语言里的卡片体系与配色 |

**退出条件：**

- 真机页面符合规定的布局：30 px 遮罩之外无内容，每张卡片距边至少 8 px。
- 验收语料的中文在真机上没有方框。
- 只用 OK 就能完成选中、展开、收起；长按永远返回。
- 在音量子页改值，当场能听到变化。

**演示：** 一本完全离线的日记，能读、能重听，中文排版是真的。

### M4 — 联网（3–4 天）

| 项 | 交付物 |
| --- | --- |
| WiFi | STA 连接、凭据进 NVS、重连策略 |
| 配网 | BLUFI over NimBLE，从设置页启动，用完即拆 |
| 发现 | mDNS 查询、`/ping` 与 `/server` 探测、采纳 limits |
| 上传 | 上传任务、幂等重试、`.sent` / `.bad` 标记 |
| 播放 | 从服务器流式播放 WAV，支持 Range 续播 |
| 时间 | SNTP、时区取自设置 |

**退出条件：**

- 全新设备用指定小程序完成配网，除 WiFi 密码外不需要任何输入就能找到服务器。
- 录音 → 上传 → 转写 → 阅读 → 播放，在真机上跑通。
- 录音中拔网不丢数据，恢复后上传能补完。
- 被拒的上传标成 `.bad`，不再重试。

**演示：** 硬件上的完整产品闭环。

### M5 — 打磨与验收（2–3 天）

| 项 | 交付物 |
| --- | --- |
| 电源 | 息屏、深睡规则、唤醒回列表 |
| 降级 | 设备端降级表逐行实现并在屏幕上看到 |
| 加固 | 量堆高水位并记录；收窄任务栈水线 |
| 交接 | 交付报告写清实测数字与剩余未验证项 |

**退出条件：**

- 产品验收清单在真机上全部通过。
- `./tools/validate.sh` 通过；`go test ./...` 通过。
- WiFi 已连时录音的堆高水位有记录、有余量。
- 交付报告分列 Build、Host tests、Device tests、Unverified。

**演示：** 验收走查。

## 3. 依赖与并行

| 里程碑 | 依赖 | 可并行 |
| --- | --- | --- |
| M0 | — | — |
| M1 | M0 | M2 |
| M2 | M0 | M1 |
| M3 | M2 | M1 |
| M4 | M1、M2 | M5 的电源部分（只需 M3） |
| M5 | M3、M4 | — |

## 4. 工作量

| 里程碑 | 天 | 把握 |
| --- | ---: | --- |
| M0 | 1 | 高 |
| M1 | 3–4 | 中：提供方对接与 Range 处理是未知数 |
| M2 | 3–4 | 中：编码 CPU 与 flash 停顿只有上真机才看得见 |
| M3 | 3–4 | 中：中文字体生成与布局要来回调 |
| M4 | 3–4 | 低：BLE 配网与真实网络下的 mDNS 是风险最高的部分 |
| M5 | 2–3 | 中 |
| **合计** | **15–19** | 单人，含硬件调试 |

如果只能投一小段，M0 + M1 + M2 已经交付了真东西：一台能可靠录音的设备，和一个能存能转写
的服务端。真正把它变成产品的是 M3 的翻阅。

## 5. 每个里程碑的完成定义

无一例外：

1. 代码提交在 `feature/*`，提交信息说明这次增量。
2. 新增的纯逻辑必须有宿主测试，收尾时跑完整门禁：
   `./tools/validate.sh --static`、`--firmware`、`go test ./...`。
3. 行为变化处更新文档，中英两版保持同步。
4. 交付报告分列 `Build`、`Host tests`、`Device tests`、`Unverified`，并写明具体跳过了
   哪些硬件检查。
5. 在既有的项目笔记里写一段：已验收什么、还欠什么、确切的构建身份。

## 6. 分里程碑的风险

| 风险 | 命中 | 缓解 |
| --- | --- | --- |
| 提供方拒收我们的 WAV（采样率、头部、体积） | M1 | 适配器只有一个文件；M1 一开始就用真实 key 试，不要拖到最后 |
| mDNS 在用户路由器上解析不到 | M4 | M4 用真实网络当场验证；设置页本来就会显示结果，兜底方案已在文档里讨论过 |
| BLUFI 小程序看不到设备 | M4 | 广播名用参考项目验证过的 `BLUFI_` 前缀；M4 用真手机测 |
| 单核上编码把界面饿死 | M2 | 复杂度 0、编解码合并任务；先简化录音页，再动编码器 |
| 中文字体过大或缺字 | M3 | 生成脚本化、覆盖测试会大声失败；实在紧张先砍 16 px 列表字体 |
| WiFi + codec 时堆不够 | M4、M5 | 设备端方案里的调参清单，M5 加一道实测高水位门 |

## 7. 明确不在范围

设备端删除与编辑、离线翻阅服务器历史、搜索、OTA、设备鉴权或 TLS、多设备账号、Web 界面。
这些在设计文档里都标了"将来接在哪"，不会变成以后才发现的意外。
